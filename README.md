# HarnKhong (หารของ) — MVP Prototype

เว็บตัวอย่างสำหรับเลือกสินค้า สร้างหรือเข้าร่วมกลุ่ม ยืนยันค่าใช้จ่าย และทดลองคำสั่งซื้อ/ข้อพิพาท ระบบกำลังทยอยเชื่อม Supabase โดยกลุ่ม คำสั่งซื้อ แชต และการแจ้งเตือนยังเป็นข้อมูลเดโมใน `localStorage` และไม่มีการชำระเงินจริง

เว็บที่เผยแพร่: https://harnkhong-mvp.netlify.app/

ซอร์สโค้ด: https://github.com/Kwankawjin/harnkhong-mvp (Private)

## ทำงานร่วมกัน

เจ้าของ repo เชิญเพื่อนผ่าน **Settings → Collaborators and teams** ก่อน เพราะ repo นี้เป็น Private จากนั้นเพื่อนสามารถรัน:

```bash
git clone https://github.com/Kwankawjin/harnkhong-mvp.git
cd harnkhong-mvp
npm ci
npm test
npm run dev
```

แนะนำให้แยก branch สำหรับงานแต่ละส่วนและเปิด Pull Request เพื่อทบทวนก่อนรวมเข้า `main` การ push ขึ้น GitHub ยังไม่ทำให้ Netlify deploy อัตโนมัติในตอนนี้

## อัปเดตบน Netlify

ไซต์นี้เผยแพร่ด้วย Netlify Drop แบบ manual deploy และยังไม่ได้เชื่อม Git สำหรับ auto deploy หลังแก้โค้ด ให้รัน `npm test` และ `npm run build` จากนั้นอัปโหลดเนื้อหาใน `dist/` ไปยังโปรเจกต์ `harnkhong-mvp` บน Netlify ไฟล์ `netlify.toml` กำหนดคำสั่ง build และโฟลเดอร์เผยแพร่ ส่วน `public/_redirects` ทำให้เปิด URL หน้าภายในเว็บได้โดยตรง

## เปิดใช้งาน

ต้องมี Node.js 20.19+ หรือ 22.12+ และ npm

```bash
npm install
npm run dev
```

หากต้องการใช้ Supabase Auth ให้คัดลอก `.env.example` เป็น `.env.local` แล้วกำหนด `VITE_SUPABASE_URL` และ `VITE_SUPABASE_PUBLISHABLE_KEY` จากโปรเจกต์เป้าหมาย (ใช้ publishable key เท่านั้น) จากนั้นตั้งค่า Auth → URL Configuration ให้ URL ของแอปและ local `http://localhost:5173` อยู่ใน redirect allow list หากไม่กำหนด environment app จะเปิดโหมดเดโมเดิม

สร้าง schema ของโปรไฟล์และที่อยู่แล้วใน migrations ภายใต้ `supabase/migrations/` และโปรเจกต์ development ปัจจุบัน บัญชีใช้อีเมล/รหัสผ่านผ่าน Supabase Auth; โปรเจกต์นี้เปิด email confirmation ผู้ใช้จึงต้องยืนยันอีเมลก่อนเข้าสู่ระบบและกรอกที่อยู่ ที่อยู่ถูกแยกจาก credentials และ RLS จำกัดให้อ่าน/แก้ไขได้เฉพาะเจ้าของ โปรเจกต์นี้ยังปิด Google provider; ปุ่ม Google จะแสดงว่าใช้ไม่ได้จนกว่าจะตั้งค่า provider ใน Supabase และ Google Cloud แล้ว

เปิด URL ที่ Vite แสดง (ค่าเริ่มต้น `http://localhost:5173/`)

```bash
npm test
npm run build
npm run preview
```

## ทดลอง flow

1. เปิดหน้าแรก → สำรวจ → เลือกกลุ่มสาธารณะที่เปิดรับ → เข้าหน้ารายละเอียดกลุ่มโดยตรง หน้าเลือกกลุ่มไม่แสดงสินค้าที่ไม่มีกลุ่ม และลิงก์สินค้าเก่าจะพาไปยังกลุ่มที่เกี่ยวข้องเมื่อมี
2. โหมดเดโมใช้ Google จำลองหรืออีเมลตัวอย่าง หากตั้งค่า Supabase จะสมัคร/เข้าสู่ระบบด้วยอีเมลและรหัสผ่านจริง (password ไม่บันทึกในแอป); Google ใช้ได้เมื่อเปิด provider configuration แล้ว บัญชีที่ยืนยันอีเมลแล้วจะกรอกที่อยู่ส่วนตัวก่อนกลับไปทำรายการ
3. หลังเข้าร่วม ดูยอดรอบใหม่แล้วกดยืนยัน
4. ไปหน้า **บัญชี** เพื่อสลับเป็นต้น เมย์ แนน แล้วยืนยันยอดของแต่ละคนในกลุ่มเดียวกัน
5. เมื่อสมาชิกครบและยืนยันรอบล่าสุดครบ หัวหน้ากลุ่มจึงบันทึกคำสั่งซื้อเดโมได้ หลังบันทึกจะล็อกสมาชิกและต้นทุนเพื่อรักษายอดที่ยืนยัน
6. ทดลองสร้างกลุ่มเฉพาะลิงก์แล้วคัดลอกลิงก์; กลุ่มนี้ไม่ปรากฏในรายการสาธารณะ
7. ใช้บัญชีผู้ขายเดโมเพื่อดูแดชบอร์ดและเพิ่มรายการสินค้า
8. ใช้ตัวเลือก **TH / EN** ที่หัวเว็บ แล้วลองสลับภาษาระหว่างกรอกฟอร์ม ข้อมูลร่างและขั้นตอนสมัครเดโมจะคงอยู่ รีโหลดแล้วจำภาษาที่เลือก
9. ให้สมาชิกที่ไม่ใช่หัวหน้าออกจากกลุ่ม ตรวจยอดใหม่และการล้างคำยืนยันเดิม; กลุ่มต้องเต็มและยืนยันรอบล่าสุดครบจึงสรุปคำสั่งซื้อได้

10. ในคำสั่งซื้อ ให้สมาชิกแจ้งชำระของตนเอง → หัวหน้ารับเรื่องตรวจยอด → ยืนยันตรวจยอดจำลองแยกแต่ละคน การแจ้งชำระไม่ทำให้ตรวจผ่านเอง
11. ผู้ขายร้านเดียวกับสินค้าเริ่มเตรียมและบันทึกจัดส่ง → หัวหน้ายืนยันรับและเริ่มตรวจรับ → จบเดโมได้เมื่อครบกำหนดและไม่มีข้อพิพาท
12. สมาชิกแจ้งปัญหา → ผู้ขายเสนอผลลัพธ์ → ผู้รายงานยอมรับหรือปฏิเสธ ต้องยอมรับร่วมกันก่อนกลับไปทำงานต่อหรือบันทึกผลคืนเงินจำลอง

ต้องการเริ่มข้อมูลใหม่: ใช้ปุ่ม **เริ่มข้อมูลเดโมใหม่** ในหน้าบัญชี ข้อมูลใช้คีย์เดิม `harnkhong-demo-v1` ส่วนภาษาเก็บแยกที่ `harnkhong-locale` และเริ่มต้นด้วยไทย คำสั่งซื้อแบบเก่าที่เก็บเพียงรหัสกลุ่มจะถูกย้ายเป็นโครงสร้างใหม่โดยไม่ถือว่าเคยชำระแล้ว ไม่ล้างกลุ่มหรือข้อมูลอื่น

กติกาสถานะ สิทธิ์ วิธีทดสอบ และข้อจำกัด: [ORDER-WORKFLOW.md](docs/ORDER-WORKFLOW.md)

## UI จำลองเพิ่มเติม

- สมัคร/เข้าสู่ระบบแบบสลับแผงตาม Auth Switch; บัญชีเดิมในเบราว์เซอร์ใช้ตัวตนและที่อยู่ที่บันทึกไว้ กรอกข้อมูลสมมติเท่านั้น
- สร้างกลุ่มเพิ่มรูป JPG/PNG/WebP ได้สูงสุด 4 รูป ไฟล์ต้นฉบับไม่เกิน 5 MB ต่อรูป ระบบย่อก่อนเก็บ แตะรูปย่อเพื่อเลือกภาพปก ลบรูปได้ก่อนสร้าง และแสดงภาพในหน้ากลุ่ม/การ์ดกลุ่ม
- หน้าคำสั่งซื้อเปิด QR ตัวอย่างพร้อมยอดส่วนแบ่งของสมาชิกและปุ่มดาวน์โหลด PNG ตัวอย่าง ภาพติดคำว่า **DEMO ONLY** สแกนชำระไม่ได้ การแจ้งชำระยังต้องรอตรวจยอดจำลองตามกฎเดิม
- หน้าบัญชีแก้ชื่อ อีเมล รูป และข้อความแนะนำตัวในหน้าต่างแก้โปรไฟล์ ยกเลิกได้โดยไม่บันทึก และไม่เปลี่ยน ID หรือบทบาทของบัญชี
- ปุ่มดูรายละเอียดกลุ่มและดูกลุ่ม/เข้าร่วมมีลูกศรและเอฟเฟกต์ตาม Flow Button พร้อมรองรับการลดการเคลื่อนไหว

ในโหมดเดโม รูป โปรไฟล์ และที่อยู่เก็บใน `localStorage` เท่านั้น ในโหมด Supabase Auth โปรไฟล์และที่อยู่เขียนลงฐานข้อมูลตาม migration; รูปโปรไฟล์ยังไม่ sync ข้ามอุปกรณ์

ทดสอบ UI: สมัครด้วยอีเมลทั่วไป → กรอกที่อยู่ → แก้โปรไฟล์แล้วรีโหลด → สร้างกลุ่มพร้อมรูป/เปลี่ยนภาพปก → สมาชิกครบและยืนยันยอด → เปิด QR/แจ้งชำระ → ตรวจว่ายังไม่ถูกยืนยันการชำระเอง ทดลองซ้ำด้วย TH/EN และหน้าจอมือถือ การดาวน์โหลด PNG ยังไม่ยืนยันการบันทึกไฟล์ใน in-app browser

## โครงสร้าง

- `src/domain.js` ตรวจข้อมูลสร้างกลุ่ม ความจุ ผลรวมเงินสตางค์ สมาชิก revision และการยืนยัน
- `src/orders.js` สถานะคำสั่งซื้อ สิทธิ์ การตรวจยอดเดโม จัดส่ง ข้อพิพาท ผลคืนเงิน ประวัติ และการย้ายข้อมูลเก่า
- `src/data.js` ข้อมูลตัวอย่าง
- `src/i18n.js` ข้อความ TH/EN ข้อผิดพลาด และการแสดงจำนวนเงินที่รักษาเศษสตางค์
- `src/prototype.js` ตัวตนเดโม การแก้โปรไฟล์ และตรวจ/ย่อรูปที่เก็บในเครื่อง
- `src/app.js` หน้าเว็บและการเชื่อม flow
- `src/style.css` design system และ responsive layout
- `tests/domain.test.js` ทดสอบกฎการเงิน การสร้างกลุ่ม สิทธิ์ และการเปลี่ยนสมาชิก
- `tests/i18n.test.js` ตรวจข้อความ ตัวแปร และจำนวนเงินที่ขอบเขต safe integer
- `tests/orders.test.js` ทดสอบเส้นทางสถานะ สิทธิ์ ข้อพิพาท การตรวจรับ ผลคืนเงิน และข้อมูลเก่า
- `tests/prototype.test.js` ทดสอบตัวตนเดิม การรักษาสิทธิ์เมื่อแก้โปรไฟล์ และขอบเขตรูปที่รับได้
- `docs/` งานวิจัย flow การตัดสินใจ และ design system

## ข้อจำกัดสำคัญ

ตอนสร้าง MVP เดิม เข้าถึงได้เฉพาะเอกสารและ flow ต้นแบบ จึงเริ่มโค้ดชุดนี้แยกจาก HarnKhong วันที่ 24 ตุลาคม 2026 จึงนำแนวทาง tests, validation, การแสดงเงิน และ TH/EN จาก `D:\test code\HarnKhong` มาปรับใช้ โดยรักษา Vite, UI, กติกาและข้อมูลเดิมไว้

ข้อความ UI รองรับสองภาษา แต่ชื่อ/รายละเอียดสินค้าตัวอย่าง ชื่อบัญชี ชื่อกลุ่ม ข้อความแชต และประวัติ/แจ้งเตือนที่บันทึกไว้คงภาษาขณะบันทึก ไม่แปลเนื้อหาผู้ใช้หรือข้อมูลเก่าอัตโนมัติ

ตรวจอัตโนมัติด้วย `npm test` และ `npm run build` ทดสอบด้วยมือเพิ่มเติมโดยป้อนราคาสินค้า `90071992547409.91` กับค่าส่ง `0.01` ในหน้าสร้างกลุ่ม: ต้องแสดงข้อผิดพลาดและไม่สร้างกลุ่ม เพราะผลรวมเกินขอบเขตจำนวนเต็มที่รองรับ ไม่มีคำสั่ง lint ในโปรเจกต์นี้

ส่วน Auth และข้อมูลโปรไฟล์/ที่อยู่ใช้ Supabase ได้เมื่อ environment ตั้งค่าแล้ว; session จัดการโดย Supabase Auth และ credentials ไม่อยู่ใน app storage ส่วนข้อมูลกลุ่ม คำสั่งซื้อ การจ่ายจำลอง ข้อพิพาท แชต การแจ้งเตือน และสินค้าเพิ่มเองยังเป็น browser-local demo ไม่มีสิทธิ์ฝั่ง server หรือ atomic join ระบบจึงยังไม่เหมาะสำหรับผู้ใช้จริง และการแชร์ลิงก์เชิญยังไม่มีการควบคุมสิทธิ์ฝั่ง server งานต่อไปคือย้ายกลุ่ม/สมาชิก/ยอด/คำสั่งซื้อ/ประวัติ/แชต/การแจ้งเตือนเข้า schema และ RPC ที่ตรวจสิทธิ์และทำงานแบบ transaction แล้วเปลี่ยนหน้าแอปให้อ่านเขียนผ่าน session จริง
