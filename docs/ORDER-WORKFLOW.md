# คำสั่งซื้อและข้อพิพาทเดโม

ทำงานในเว็บ Vite เดิม ใช้ `harnkhong-demo-v1` และ TH/EN เดิม ไม่เพิ่ม backend, payment provider หรือ dependency ไม่มีการรับฝาก ถือ โอน ปล่อย หรือคืนเงินจริง

## สิ่งที่มีเดิมและสิ่งที่เพิ่ม

เดิมมีการหารสตางค์ สมาชิก/หัวหน้า revision คำยืนยันยอด บัญชีเดโม ข้อมูล localStorage แชต แจ้งเตือน และประวัติกลุ่ม คำสั่งซื้อเดิมเก็บเพียงรหัสกลุ่ม ยังไม่มีสถานะชำระ/จัดส่ง ข้อพิพาท หรือประวัติคำสั่งซื้อ

เพิ่ม `src/orders.js` เพื่อบังคับเส้นทางและสิทธิ์ด้วยฟังก์ชันที่ไม่แก้ input ผูกหน้าเดิมกับฟังก์ชันนี้ เก็บคำสั่งซื้อ การล็อกกลุ่ม ประวัติ และแจ้งเตือนพร้อมกันก่อนแสดงความสำเร็จ หากบันทึกไม่สำเร็จไม่เปลี่ยน state คำสั่งซื้อในหน่วยความจำ

## เส้นทางและผู้ดำเนินการ

| จาก → ไป | ผู้ดำเนินการ / เงื่อนไข |
| --- | --- |
| ยังไม่สร้าง / `waiting_for_members` → `pending_payment` | หัวหน้าปัจจุบัน สมาชิกครบและยืนยัน revision ปัจจุบันครบ |
| `pending_payment` → `payment_secured` | เกิดจากตรวจยอดจำลองครบทุกคนเท่านั้น |
| `payment_secured` → `preparing_order` | ผู้ขายร้านเดียวกับสินค้า และยอดเดโมผ่านครบ |
| `preparing_order` → `shipped` | ผู้ขายบันทึกเลขติดตามหรือลิงก์ http(s) อย่างน้อยหนึ่งอย่าง |
| `shipped` → `delivered` | หัวหน้ากลุ่มยืนยันรับสินค้า |
| `delivered` → `inspection_period` | หัวหน้าเริ่มช่วงตรวจรับ |
| `inspection_period` → `completed` | หัวหน้า หลังครบกำหนด ยอดเดโมครบ ไม่มีข้อพิพาทค้าง |
| สถานะตั้งแต่ `pending_payment` ถึง `inspection_period` → `disputed` | สมาชิกของคำสั่งซื้อแจ้งปัญหา |
| `disputed` → สถานะก่อนเปิดเรื่อง | ผู้ขายเสนอ resume และผู้รายงานยอมรับ |
| `disputed` → `refunded` | ผู้ขายเสนอ refund และผู้รายงานยอมรับ พร้อมบันทึกผลคืนเงินจำลอง |

`completed` และ `refunded` ย้อนกลับไม่ได้ `disputed` ข้ามไปสถานะอื่นเองไม่ได้ ไม่มีปุ่มปล่อยเงินจริง และไม่มี dropdown เปลี่ยนสถานะอิสระ

สถานะชำระแยกจากคำยืนยันยอด: `unpaid` → สมาชิกแจ้งของตนเองเป็น `payment_reported` → หัวหน้ารับเรื่องเป็น `verification_pending` → หัวหน้าตรวจเดโมเป็น `verified` การตรวจนี้ไม่มีหลักฐานธนาคาร หากให้แจ้งใหม่ต้องระบุเหตุผลและกลับไป `unpaid`

| บทบาท | สิทธิ์ |
| --- | --- |
| สมาชิกในคำสั่งซื้อ | ดูคำสั่งซื้อ/ยอด แจ้งชำระของตน เปิดปัญหา ตอบข้อเสนอที่ตนรายงาน |
| หัวหน้ากลุ่ม | สิทธิ์สมาชิก สร้างคำสั่งซื้อ ตรวจยอดเดโม ยืนยันรับ เริ่มตรวจรับ จบเดโมตามเงื่อนไข |
| ผู้ขายร้านที่เกี่ยวข้อง | ดูรายการของร้าน เตรียม/แก้ข้อมูลจัดส่ง เสนอผลข้อพิพาท |
| บุคคลภายนอก / ผู้ขายต่างร้าน | ดูหรือแก้คำสั่งซื้อไม่ได้ |

สมาชิกไม่แก้ยอดชำระของคนอื่น ผู้ขายไม่ตรวจยอดแทนหัวหน้า หัวหน้าไม่ตัดสินข้อพิพาทฝ่ายเดียว ผู้ขายที่เป็นผู้รายงานเองเสนอปิดเรื่องตนเองไม่ได้ ไม่มีบทบาทผู้ไกล่เกลี่ยในรอบนี้

## ข้อพิพาท ประวัติ และการตรวจรับ

- เหตุผลมีไม่ได้รับสินค้า ไม่ตรงรายละเอียด ของขาด/ผิด ปัญหาจัดส่ง ข้อโต้แย้งชำระ และอื่น ๆ ต้องมีคำอธิบาย กรอกหลักฐานอ้างอิงเป็นข้อความได้ ไม่มีบริการอัปโหลดไฟล์
- ก่อนส่งรายงานและตอบข้อเสนอมีการยืนยัน เก็บผู้รายงาน เวลา เหตุผล ข้อเสนอ/การปฏิเสธ ผู้เสนอ ผู้ตอบ และผลแก้ไข ขณะค้างเรื่องจะหยุดการชำระ/จัดส่ง/จบเดโม ไม่สร้าง refund อัตโนมัติ
- เมื่อยอมรับผลคืนเงิน บันทึกเฉพาะผลจำลองและยอดของสมาชิกที่ตรวจเดโมแล้ว หากยังไม่ตรวจใครยอดเป็นศูนย์ ไม่มีการจ่ายออกจริง
- ประวัติเรียงตามลำดับดำเนินการ เพิ่มต่อท้ายทุกครั้ง: สร้าง/สมาชิกครบ แจ้ง/ตรวจยอด เปลี่ยนสถานะ จัดส่ง เริ่ม/จบตรวจรับ ข้อพิพาท/ข้อเสนอ/ตอบ ผลคืนเงิน และจบคำสั่งซื้อ การกระทำที่ถูกปฏิเสธไม่สร้าง success event
- ช่วงตรวจรับตั้งได้ 1–720 ชั่วโมงเต็ม ค่าเริ่มต้น 24 ชั่วโมงเป็นสมมติฐานเดโม ไม่ใช่กติกาธุรกิจจริง เริ่มนับเมื่อหัวหน้ากดเริ่ม หาก resume หลังข้อพิพาทให้เริ่มช่วงเต็มใหม่ ไม่มี timer จบอัตโนมัติ รีเฟรชเมื่อครบกำหนดเพื่อใช้ปุ่มจบ
- ข้อมูลขนส่งกรอกเองและแสดงว่ายังไม่ตรวจสอบ เก็บวันที่ส่งครั้งแรกและประวัติการแก้ข้อมูล ลิงก์ยอมรับเฉพาะ http(s) ไม่มี username/password ใน URL
- คำสั่งซื้อเดิมย้ายแบบ idempotent ไม่ถือว่าชำระแล้ว หากสมาชิก/คำยืนยันไม่พร้อมให้รอ ตรวจกลุ่มและหัวหน้าปัจจุบันอีกครั้งก่อนเริ่ม ไม่รู้เวลาสร้างเดิมจึงแสดงว่าไม่ทราบ

## วิธีทดสอบ

รัน `npm test` และ `npm run build` สำหรับเฉพาะงานนี้ใช้ `node --test tests/orders.test.js tests/i18n.test.js` ไม่มี lint script ตั้งไว้

1. สร้างกลุ่ม 2 คน ยอด 100.01 บาท ค่าส่ง/บริการศูนย์ สลับต้นและเมย์เข้าร่วม/ยืนยัน ตรวจว่าได้ 50.01 + 50.00 บาท ก่อนสมาชิก/คำยืนยันครบต้องสร้างคำสั่งซื้อไม่ได้ สมาชิกทั่วไปสร้างไม่ได้
2. หัวหน้าสร้างคำสั่งซื้อ กำหนดตรวจรับ 1 ชั่วโมง ลองแก้สมาชิก/ต้นทุนหลังสั่ง ต้องไม่ได้
3. แจ้งชำระแต่ละคน ตรวจว่าเป็น reported เท่านั้น สมาชิกไม่มีสิทธิ์ตรวจเอง หัวหน้าต้องรับเรื่องและตรวจเดโมทีละขั้น หลังครบจึงเตรียมสินค้าได้
4. สลับผู้ขายอีกร้าน ต้องเข้าถึงคำสั่งซื้อไม่ได้ กลับผู้ขายเจ้าของร้าน เตรียมและกรอกเลขจัดส่งที่ระบุว่าเป็น QA จำลอง ตรวจสถานะ/history
5. หัวหน้ายืนยันรับ เริ่มตรวจรับ ต้องเห็นเริ่ม/กำหนดสิ้นสุด ปุ่มจบก่อนกำหนดปิดอยู่ Unit test ใช้เวลาที่กำหนดตรวจทั้งก่อนและตรง deadline โดยไม่รอจริงหรือแก้นาฬิกาเครื่อง
6. เมย์เปิดปัญหา คำสั่งซื้อต้องเป็น disputed ไม่มีการจบ/คืนเงินเอง ผู้ขายเสนอ resume เมย์ปฏิเสธ ตรวจว่าประวัติยังอยู่ ผู้ขายเสนอใหม่ เมย์ยอมรับ ต้องกลับสถานะเดิมและเริ่มช่วงตรวจรับใหม่
7. เปิดปัญหาใหม่ เสนอ refund และยอมรับ ต้องมีผลคืนเงินจำลองกับเหตุผลและประวัติครบ ห้ามย้อนสถานะหรือเปิดเรื่องใหม่ใน terminal state
8. รีโหลด ดูว่าสถานะ ยอด การจัดส่ง และข้อพิพาททั้งที่ปิดและค้างยังอยู่ สลับ TH/EN และตรวจหน้าจอมือถือ

## เกณฑ์ยอมรับและผลตรวจ

ผลตรวจล่าสุด: `npm test` ผ่าน 32/32 (domain 12, i18n 3, order 17), `npm run build` ผ่าน, ตรวจ syntax ของ `src/app.js` และ `src/orders.js` ผ่าน และ `git diff --check` ผ่าน ทดสอบผ่านหน้าเว็บด้วยบัญชีสมาชิก/หัวหน้า/ผู้ขาย รวมการรีโหลด ข้อพิพาทและผลคืนเงินจำลอง ภาษา TH/EN และหน้าจอ 390×844 ไม่พบข้อความ error/warn ใน console ของรอบทดสอบนี้

| เกณฑ์ MUST | หลักฐานตรวจ |
| --- | --- |
| 1 เส้นทางถูก/ผิด | unit tests ลำดับปกติ การข้ามสถานะ terminal และ UI จัดส่ง/ตรวจรับ |
| 2 สมาชิก/คำยืนยันครบ | domain + order tests และ UI ก่อนสร้าง |

| 7 ประวัติสำคัญ | unit tests และ UI หลังรายงาน/ตรวจ/จัดส่ง/ข้อเสนอ/ผลแก้ไข |

SHOULD: ทำแบบฟอร์มปัญหา (B1), ขนส่ง (B2), ตรวจรับ (B3), feedback TH/EN (B5) ส่วน 2% (B4) ยังไม่มีฐานคำนวณ/ผู้จ่ายที่ยืนยัน จึงไม่เพิ่มหรือหักเอง คงค่าบริการเดิม

## ข้อจำกัดและงานอนาคต

browser-local demo ไม่ใช่ server authorization ผู้ใช้แก้ localStorage ตัวตน เวลา และประวัติได้ ไม่มีการซิงก์ข้ามเครื่อง/แท็บหรือการเขียนพร้อมกันที่ปลอดภัย ไม่มีการตรวจธนาคาร หลักฐานอัปโหลด ผู้ไกล่เกลี่ย หรือระบบเงินจริง ต้องออกแบบ backend/auth/transaction และกติกา production ก่อนเปิดใช้จริง

ไม่มีการยืนยันว่าฟีเจอร์ทั้งหมดทุกเบราว์เซอร์ผ่านการทดสอบ การจบหลังครบเวลาใช้ unit test; browser test ตรวจการบล็อกก่อนเวลาและข้อพิพาท ไม่รอหนึ่งชั่วโมงจริง
