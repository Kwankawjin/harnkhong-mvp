# Decisions and assumptions — 23 ตุลาคม 2026

- ไม่มี repo เดิมใน workspace หรือพาธ `D:\test code\HarnKhong` และ Build Kit ไม่มีโค้ด จึงสร้างโปรเจกต์ใหม่ในโฟลเดอร์ส่งมอบ โดยอิง flow ของ Prototype HTML ที่อ่านได้ในแชต ChatGPT โปรเจกต์ “หารของ” ไม่กล่าวอ้างว่าเป็นการแก้ source เดิม
- ใช้ Vite + JavaScript modules และ CSS ปกติ เพื่อลด dependency; ไม่มี backend ในชุดไฟล์
- ราคา authoritative ใช้ integer satang; การป้อนบาทรับทศนิยมสูงสุด 2 ตำแหน่ง; เศษสตางค์ให้สมาชิกตามลำดับเข้ากลุ่ม
- ให้สร้างกลุ่มขั้นต่ำ 2 สูงสุด 20 คน; หัวหน้ากลุ่มต้องโอนสิทธิ์ก่อนออก
- ทุกการเปลี่ยนสมาชิกหรือต้นทุนเพิ่ม revision และล้าง approvals; order demo ต้องสมาชิกเต็มและ approvals ปัจจุบันครบ
- ราคาต่อคนบน card เป็น **ประมาณเมื่อสมาชิกครบ** เพื่อไม่สื่อว่าเป็นยอดที่ตกลงแล้ว; หน้า group แสดงยอดปัจจุบันของแต่ละคนและ revision
- ค่าบริการเริ่มต้น 0 และแสดงสินค้า ค่าส่ง ค่าบริการแยกกัน
- เริ่มจากสินค้าทางกายภาพและงานพิมพ์ที่มีเงื่อนไขตรวจสอบได้ หลีกเลี่ยงการแชร์สมาชิกบริการดิจิทัลซึ่งอาจขัดข้อกำหนดผู้ให้บริการ
- สลับบัญชีเดโมได้เพื่อทดลองยืนยันยอดหลายคน; ไม่ถือเป็น auth หรือการควบคุมสิทธิ์จริง
- ไม่มี Push prompt; in-app notification เพียงพอสำหรับ MVP นี้

## เสริมจาก HarnKhong — 24 ตุลาคม 2026

- ใช้เว็บ Vite นี้เป็นฐานต่อ นำเฉพาะแนวทาง tests/validation/เงิน/ภาษาไปปรับใช้ ไม่ย้าย framework หรือข้อมูลจำลองต้นทางมาทับ และไม่เพิ่ม dependency
- การสร้างกลุ่มและ preview ตรวจผลรวมผ่าน `totalCost` เดียวกัน; `createGroup` ตรวจชื่อ ID ประเภท public/link และความจุเดิม 2–20 คนก่อนบันทึก ID ต้องเป็นข้อความไม่ว่างและไม่มีช่องว่างหัวท้าย
- จำนวนเงินยังเป็น integer satang และใช้ parser เดิม แยกบาทกับเศษสตางค์ตอนแสดงผลและใส่ค่าในฟอร์ม เพื่อรักษาความแม่นยำถึง `Number.MAX_SAFE_INTEGER` สตางค์
- ภาษาเริ่มต้นไทยตาม Prototype เลือก TH/EN ได้และเก็บที่ `harnkhong-locale` แยกจากข้อมูลเดิม `harnkhong-demo-v1` สลับภาษาแล้วเก็บข้อมูลร่างและขั้นตอนฟอร์มไว้ การเลือกภาษาเริ่มต้นของระบบจริงยังเป็นคำถามเปิด
- ชื่อสินค้า/บัญชี/กลุ่มและเนื้อหาที่บันทึกไว้ไม่แปลอัตโนมัติ ข้อมูลตัวอย่าง ประวัติกลุ่มและแจ้งเตือนเก่าจึงอาจยังเป็นไทยในหน้าอังกฤษ ส่วนข้อความจำลองใหม่เก็บภาษาขณะสร้าง
- คงกติกาความจุ การโอนหัวหน้า revision และเงื่อนไขพร้อมสั่งซื้อที่ระบุไว้เดิม เป็นการตัดสินใจของ Prototype นี้ ต้องให้ทีมยืนยันก่อนใช้จริง ไม่ยกระดับเป็นข้อกำหนดที่ RawData ยืนยันแล้ว
- กลุ่มเฉพาะลิงก์ยังใช้ URL กลุ่มและซ่อนจากรายการสาธารณะ ไม่มี token/หมดอายุ/เพิกถอนลิงก์ตามที่ยังไม่ได้ตัดสินใจ และ localStorage ยังเปิดข้อมูลข้ามเครื่องไม่ได้

ข้อกำหนดหลักอ้างอิง `D:\test code\HarnKhong\RawData.md` หัวข้อ 2 ส่วนคำถามผลิตภัณฑ์ที่ยังไม่ยืนยันอยู่ในหัวข้อ 4–5 และแผนการนำงานเดิมมาใช้ที่ `D:\test code\HarnKhong\plans\001-reuse-for-mvp.md` ไม่คัดลอกข้อกำหนดทั้งชุดมาสร้างแหล่งข้อมูลซ้ำ

## คำสั่งซื้อและข้อพิพาทเดโม — 24 ตุลาคม 2026

- ใช้ business logic ใน `src/orders.js` ร่วมกับ `domain.js` และ localStorage เดิม ไม่เพิ่ม dependency หรือ state manager
- ผู้ใช้ยืนยันรูปแบบแก้ข้อพิพาทร่วมกัน: ผู้ขายเสนอ แล้วผู้รายงานยอมรับก่อนปิดเรื่อง ไม่มีผู้ขายหรือหัวหน้าปิดเอง ประวัติข้อเสนอที่ปฏิเสธคงอยู่
- คงรหัสสถานะ `payment_secured` สำหรับลำดับเดโม แต่แสดง “ตรวจยอดครบแล้ว (จำลองเท่านั้น)” และบันทึกว่าไม่มี actual payment verification ไม่อ้าง escrow หรือธุรกรรมธนาคาร
- ล็อกสมาชิก หัวหน้า ต้นทุน และคำยืนยันหลังเริ่มคำสั่งซื้อ เพื่อไม่ให้ยอดที่กำลังตรวจเปลี่ยน คำสั่งซื้อเก่าที่ยังไม่พร้อมคงแก้กลุ่มได้และตรวจเงื่อนไขซ้ำตอนเริ่ม
- ระยะตรวจรับเดโม 1–720 ชั่วโมงเต็ม เริ่มต้น 24 ชั่วโมง เป็นข้อสมมติเพื่อสาธิต หลังแก้ข้อพิพาทแล้วกลับเข้าตรวจรับให้เริ่มช่วงเต็มใหม่ ไม่มีจบรายการอัตโนมัติ ต้องให้ทีมยืนยันก่อนใช้จริง
- ผลคืนเงินเดโมบันทึกยอดรวมเฉพาะส่วนแบ่งที่ตรวจยืนยันเดโมแล้ว (อาจเป็นศูนย์) หลังทั้งสองฝ่ายยอมรับ ไม่มีการโอนหรือคืนเงินจริง กติกาคืนเงินบางส่วน/ฝ่ายกลาง/ค่าธรรมเนียมยังต้องออกแบบ
- ยังไม่พบข้อกำหนดยืนยันฐานคำนวณและผู้จ่าย 2% จึงคงค่าบริการเดิมและไม่เพิ่มการหักค่าธรรมเนียม/ยอดผู้ขายเอง
- ข้อมูลเก่าที่เป็นรหัสกลุ่มย้ายโดยไม่อนุมานการชำระหรือเวลาสร้างเดิม เก็บประวัติการนำเข้า และไม่ล้างข้อมูลเดิม
- สิทธิ์ ตัวตน เวลา และ audit history ในเบราว์เซอร์แก้ไขได้ ไม่ใช่ auth หรือหลักฐานที่ป้องกันการแก้ไข เมื่อใช้จริงต้องตรวจทั้งหมดบน server
